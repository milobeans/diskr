Documentation

Installation, the interface, keys, reports and how diskr measures disk usage. Press ⌘K or / to search.

Install

diskr runs on macOS 15 or newer, on Apple Silicon and Intel. The Homebrew tap installs a native archive and verifies its checksum; no Rust toolchain is needed:

brew tap milobeans/diskr https://github.com/milobeans/diskr
brew install milobeans/diskr/diskr

Update with brew update, then brew upgrade milobeans/diskr/diskr. Remove it with brew uninstall milobeans/diskr/diskr.

If you do not use Homebrew, download a verified native release below. Apple Silicon archives are named aarch64-apple-darwin; Intel archives are x86_64-apple-darwin. Both include dependency license notices alongside the executable.

Native installer without Homebrew

In a new, empty directory, download the installer and checksum list from the latest release:

curl --fail --location --remote-name https://github.com/milobeans/diskr/releases/latest/download/install-diskr.sh
curl --fail --location --remote-name https://github.com/milobeans/diskr/releases/latest/download/SHA256SUMS
checksum=$(awk '$2 == "install-diskr.sh" { print }' SHA256SUMS)
test -n "$checksum" && printf '%s\n' "$checksum" | shasum -a 256 -c -

Only after verification reports OK, run the installer:

sh install-diskr.sh

The release installer is pinned to its own version. It selects your Mac's architecture, verifies the downloaded archive and executable version, and installs the executable and license notices under ~/.local.

Check each release's notes and, when provided, distribution.json for its signing status. Signed releases include notarized, stapled DMGs. Version 0.1.83 archives are unsigned and not notarized; macOS or organization policy may require another installation route. The installer does not remove quarantine or change security policy.

PATH and custom install locations

The default native install can be launched directly:

"$HOME/.local/bin/diskr" ~/Downloads

To run diskr by name in the current shell, add the install directory to PATH:

export PATH="$HOME/.local/bin:$PATH"

For future zsh sessions, add that same export line once to ~/.zprofile. The installer prints guidance and leaves your shell files unchanged. To choose a different install prefix, run sh install-diskr.sh --prefix /absolute/path; the executable goes in that prefix's bin directory.

Install with Rust

If you already have Rust 1.88 or newer:

cargo install diskr --locked

To build from a local checkout, run cargo install --path . --locked. Cargo installs into its configured bin directory.

First run

Start with a familiar folder. This opens the browser without deleting anything:

diskr ~/Downloads
  1. Measure. Press S to size visible folders. Press . to include hidden ones.
  2. Inspect. Select a folder and press t for its largest files, or ⏎ to open it.
  3. Choose. Press i for details or f to reveal an item in Finder. Review before using d to move it to the Trash.

? explains every key, Esc cancels the focused scan or closes a view, and q quits. Run diskr without a path to browse your home folder. Tab cycles Files, Disks, Packages and Reclaim; b toggles a full-width active view.

Go to a folder or saved profile

Press g to choose a common location, a saved root or a package profile. Use ↑/↓ and ⏎, or press / to enter a path. Profile entries show their inventory scope and origin; imported profiles from another machine cannot run until you create a local profile. Esc leaves path entry or closes the chooser.

Limited access

A limited access notice or ≥ size means the scan could not measure everything. The displayed size is a known lower bound. macOS privacy controls, ordinary file permissions and unavailable volumes can all limit coverage; diskr remains usable for folders it can read.

To include privacy-protected folders, you can grant Full Disk Access to the app hosting your terminal:

  1. Open System Settings → Privacy & Security → Full Disk Access.
  2. Enable your terminal app, such as Terminal or iTerm, or the editor hosting an integrated terminal. Only do this for an app you trust.
  3. Quit and reopen that app if macOS requests it, reopen diskr, then press r to refresh.

Full Disk Access is optional and does not override every filesystem permission. If a result remains partial, inspect its warning and try a readable folder. The in-app ? help includes this recovery path. Apple explains the permission in its Privacy & Security settings guide.

Files

diskr — ~

Scroll the terminal sideways to see every column.

The Files pane sorts by allocated size with a share bar for every row. Inline tags such as [cache] and [build] mark reclaimable folders as you browse, and a ↑ or ↓ badge shows how much a folder changed relative to its session baseline. o cycles sort modes, including sorting by growth.

A complete cached measurement loaded when diskr starts becomes that folder's session baseline. If there is no complete cache, the first complete scan establishes it. Repeated scans, refreshes and navigation keep that comparison; partial measurements do not display a growth delta. Saved and named baselines are separate comparison points.

Lazy, cached scanning

Scans start in small batches around the current selection, so opening / or another broad folder does not immediately walk every subtree. Press S to fill in every missing or stale visible size without refreshing the folder or invalidating sizes that are already fresh; r refreshes the view and rescans everything visible.

Sizes are cached between runs. On relaunch, diskr uses reliable macOS FSEvents replay to identify changed folders. Unchanged trees can stay fresh without a rescan; unavailable or unreliable replay marks cached results stale for revalidation.

Allocated and apparent size

APFS clones, sparse files and compressed files make a file's logical size diverge from what it occupies on disk. diskr tracks both, sorts by allocated size, and shows apparent size when they differ. Folders or entries that cannot be read are flagged as lower bounds with ≥ rather than counted as zero.

Acting on files

Reveal any item in Finder with f, open it with the default app with O, copy its path with y, or open Terminal at its location with s. d moves files or project dependency folders to the Trash after confirmation; v marks items and a marks everything visible so you can act on several at once. c renames and n creates a folder.

Reclaim

diskr — ~

Scroll the terminal sideways to see every column.

Tab to the Reclaim pane, or run diskr --reclaim ~, to find caches, build artifacts and package stores. Every finding carries a class and the reason for it:

ClassMeaningExamples
safePure cache, regenerated automatically~/Library/Caches, Xcode DerivedData, Homebrew, npm and pip caches
regenerableCosts a rebuild or re-downloadnode_modules, target, .venv, Cargo registry, iOS DeviceSupport
riskyMay hold data you cannot recreateTrash, Xcode Archives, simulator devices, Docker data, .next output

In the pane, ⏎ lists a finding's paths. Select a path there and use d to move it to the Trash after confirmation. R rescans, and E empties the Trash when the report lists a Trash finding. The --reclaim report only reports; it never deletes anything. Trash is classified as risky because emptying it permanently removes discarded files; its contents are not regenerated cache.

How findings are detected

The detector runs two passes: a fixed-location pass over well-known paths (~/Library/Caches, Xcode DerivedData, Homebrew, Docker and others) and a bounded recursive pass that finds repeated build-artifact folders (node_modules, target, .venv, __pycache__, .next, .gradle). Both use the same bulk scanner for sizing.

Artifact classifications require supporting project or environment markers; a name such as target alone is not a cleanup recommendation. Reports disclose their depth, mount and hidden/cache exclusions. Esc or Ctrl+C cancels a focused reclaim scan, and cancelled findings are never published as a complete report.

Note

Candidate bytes are not a promise of freed space. APFS clones, snapshots and links can retain blocks, and moving files to the Trash does not free their storage until the Trash is emptied.

Top files

diskr — ~/Library

Scroll the terminal sideways to see every column.

Press t on any folder to open a full-width browser of the largest files beneath it, however deep. ⏎ or f reveals the selection in Finder, O opens it, d moves it to the Trash, and t or Esc returns. Top Files counts each regular-file inode once within the selected root. Its coverage indicators still apply: unreadable data makes the total a lower bound, and allocated bytes are not a promise of space freed. From a script, use diskr --top 20 ~/Downloads.

Changes and baselines

Save a baseline now and compare whenever you like. diskr keeps the latest baseline per root, and named baselines let you pin comparison points such as “before cleanup”.

$ diskr --save ~
$ diskr --diff ~
Diff for /Users/demo
Baseline captured 3d ago
Total: 44 GiB disk → 50 GiB disk  (+5.1 GiB)
    +2.7 GiB  grew       .ollama
    +1.5 GiB  grew       Downloads
    +960 MiB  grew       code

In the TUI, B saves a baseline for the current folder. Baselines are stored under ~/Library/Application Support/diskr/, and diffs do not overwrite them. Named baselines and saved inventory profiles are covered in Baselines and profiles.

Packages and projects

Press p for the packages pane, and p again while it is focused to switch views. The System view lists Homebrew formulae and casks, npm, pip, Cargo and Bun installs with per-package sizes. The Projects view finds dependency folders under the current path and how much each costs. In System view, u filters to dependency leaves, and x (or d) runs the owning manager's uninstall flow after confirmation. In Projects view, d moves the selected dependency folder to the Trash after confirmation. A leaf has no known package-manager dependents; you or a script may still use it.

How sizes are measured

Reports distinguish empty inventories from unavailable managers, command failures, malformed output and partial results, and keep inventory and dependency-graph warnings in package details. Sizes describe known allocation within their stated footprint: directory trees, app and manager metadata, installed binaries, RECORD-listed files, or installer metadata. A ≥ marker denotes a partial measurement; manager totals also report unknown and limited-scope footprints.

Manager details identify the executable and package roots used by the scan, and uninstall uses that retained installation scope. Cargo follows CARGO_INSTALL_ROOT, its user configuration and CARGO_HOME; Homebrew, Bun, npm and pip supply their active locations through their inventory commands.

Dependency counts

Project counts are unique declared names across runtime, development, optional, peer and build groups, not a count of installed transitive packages. Cargo target tables and Python PEP/Poetry groups are included; Python names are normalized and merged across requirements and pyproject declarations. Go indirect requirements are excluded. Manifests are never executed: dynamic declarations, executable Gemfiles and parse failures show unknown or lower-bound counts with warnings.

Disks and free space

diskr --space explains differences between df and Finder: mount-level totals, APFS container free space, what is actually available to you, and the local snapshots that can pin deleted data.

$ diskr --space ~
Space report for /Users/demo
Mount: /System/Volumes/Data (apfs, /dev/disk3s5)
Total: 460 GiB
Used: 446 GiB
Free blocks: 14 GiB
Available to user: 14 GiB
APFS container disk3: 460 GiB total / 14 GiB free
Local snapshots: 3

diskr --thin-snapshots 10G ~ previews snapshot thinning as a dry run; add --yes to request it. In the TUI, i on a disk opens its details, where s retries snapshot discovery and a retries APFS container discovery independently.

Reports

Each example is separate: copy only the command you want to run. Top Files, reclaim, baseline save/diff, space and package reports support --json.

Largest files

diskr --top 20 ~/Downloads

Cleanup candidates

diskr --reclaim ~

Save a baseline

diskr --save ~/Downloads

Compare with that baseline

diskr --diff ~/Downloads

APFS space and snapshots

diskr --space ~

Packages and projects

diskr --packages ~

Projects in a selected scope

diskr --packages --projects-only --max-depth 3 --exclude archive ~/code

Selected package managers

diskr --packages --manager cargo --manager brew --no-projects ~

Snapshot thinning

Preview a request to release 10 GiB held by local Time Machine snapshots. This command does not delete snapshots:

# Preview only; no snapshots are removed
diskr --thin-snapshots 10G ~
Apply snapshot thinning

This requests real snapshot removal from macOS. Removed local recovery points cannot be restored through diskr, and the amount freed depends on macOS and current snapshots. Run this only after reviewing the preview:

# Apply: request permanent local snapshot removal
diskr --thin-snapshots 10G --yes ~

JSON output

JSON reports use schema_version: 1 and share a common report, root, root_identity, scope, coverage, warnings, timing and numeric_semantics contract while retaining earlier report-specific fields. coverage.complete is false for unreadable or skipped data, utility failures, unknown dependency counts, or incomplete and limited package footprints. Explicit discovery depth and policy exclusions remain visible in scope metadata.

Byte counts are unsigned 64-bit JSON integers, so use an integer-capable parser when values may exceed JavaScript's safe-number range. Signed byte deltas are decimal strings, timestamps are Unix seconds, and elapsed time is monotonic milliseconds. root_identity is a reversible Unix path encoding; root is the human-readable path.

Package JSON includes every manager's scan_state and each package's dependency evidence; incomplete graphs have unknown leaf status. dep_count: null marks an incomplete count, alongside known_dep_count, dependency_count_complete and dependency_warnings. APFS failures keep their error text and an apfs_diagnostic object whose kind is timeout, tool_failure or malformed_output.

Exit codes

StatusMeaning
0A usable report, including partial reports by default
1An error
2With --strict: the report printed but was incomplete; the diagnostic goes to stderr

--strict does not undo a requested --save. JSON stdout stays parseable and contains no progress or error prose, and closed output pipes still finish normally.

Filters

--min-size SIZE filters allocated-size rows in --top, --reclaim and --packages; --class safe|regenerable|risky filters reclaim categories. Unknown, partial or limited-scope sizes are retained. Filters affect rows, not scan totals or completeness, and JSON includes the filter settings and counts of removed rows.

Follow-up commands printed by reports quote paths for macOS zsh; paths containing control or non-UTF-8 bytes use $'\xNN' byte escapes.

Package scope

Scope controls apply to --packages and --save-profile. --projects-only never invokes package managers. --manager is repeatable and selects brew, brew-cask, npm, pip, cargo or bun, with projects still included unless --no-projects is set. --max-depth accepts 0 (the selected folder only) through 64, default 5. Repeat --exclude for exact root-relative project subtrees, not shell globs; absolute paths and .. are rejected. Exclusions affect discovery, not the footprint of an included project's dependency tree.

Baselines and profiles

The default --save/--diff pair keeps one latest baseline per root, retaining up to 512 roots. Named captures are separate, immutable, and never silently replace that latest baseline. Names use 1–80 ASCII letters, digits, ., _ or -.

These are independent operations. Copy and run only the one you need.

Capture a named baseline

diskr --save --baseline before-cleanup ~/code

Compare with a named baseline

diskr --diff --baseline before-cleanup --json

List saved captures and profiles

diskr --baselines list --json

Protect a capture from pruning

diskr --baselines pin before-cleanup

Remove pin protection

diskr --baselines unpin before-cleanup

Export captures and profiles

diskr --baselines export /tmp/diskr-baselines.json

Import a validated library

diskr --baselines import /tmp/diskr-baselines.json

Prune old captures

Preview keeping the newest ten unpinned captures plus every pinned capture:

# Preview only; no captures are removed
diskr --baselines prune 10
Apply baseline pruning

This removes older unpinned captures after writing a recoverable library backup. Keep the backup path printed by the command:

# Apply: back up the library, then remove older unpinned captures
diskr --baselines prune 10 --yes

Without a path, a named diff uses its stored root; an explicit different root is rejected, not retargeted. The library lives alongside history as baseline-library.json, bounded at 16 MiB, 2,048 named captures and 256 profiles. Retention, capacity and source identities are visible in the list.

Pruning requires --yes, keeps every pinned record and writes a backup before removal. Exports refuse to overwrite an existing file. Imports validate before atomically merging, reject conflicting names, preserve machine and raw-root identity, and never replace latest-root history; re-importing identical records is harmless. A named cross-machine comparison is explicitly warned and partial for --strict, and imported foreign profiles cannot run until recreated locally with an explicit root, scope and new name.

Saved inventory profiles

Save a project scope, then open it with g in the TUI or run the package report:

diskr --save-profile work --projects-only --max-depth 3 --exclude archive ~/code
diskr --packages --profile work --json

Preview removing an obsolete profile:

# Preview only; the profile is retained
diskr --baselines remove-profile work

Profiles save a package inventory root and scope without invoking managers. --packages --profile NAME accepts report filters, JSON and strict options, but not another path or scope override. Saving an existing name is an error; remove obsolete profiles with --baselines remove-profile, which previews by default and requires --yes, with a backup.

How it works

The scanner

The core scanner calls getattrlistbulk(2) with a packed attribute list requesting name, object type, logical size and allocated size. The kernel fills a buffer with dozens of entries per call, and diskr parses the packed binary layout directly without allocating per entry on the hot path. A custom work-stealing thread pool fans out across subfolders. Performance depends on the filesystem, tree shape and cache state; no fixed speedup is promised.

Sizes count regular-file content only: symlink targets and folders' own metadata blocks are not added, so totals run slightly under du and Finder. The size cache and history baselines are persisted as JSON through serde_json.

Responsiveness and cancellation

Startup renders before state loading, with q, Esc and Ctrl+C cancellation. Folder enumeration runs off the UI loop in bounded batches, and navigation or refresh invalidates older generations. Cancelling enumeration in Files labels the shown list partial; r retries. Package rows appear as soon as each manager or project is ready, the inventory footer reports elapsed time and ready stages, and cancelling keeps the ready rows with a partial marker. Quitting cancels read-only discovery, while pending changes finish gracefully.

Shared scans

Independent scans of the same root, identity, policy, freshness and requested Top Files capacity share in-flight work. Each subscriber keeps its own cancellation, so one cancelled caller cannot cancel another. Completed results are not retained as a cache, and refreshes or changes invalidate matching in-flight work.

Accuracy notes

Baseline and cleanup totals deduplicate hardlinks within their selected scope. Independently measured Files rows may share an inode and must not be summed as an exact unique-root total; use Top Files for that. Human terminal output escapes control characters from filenames and external tools, while JSON keeps normal structured escaping.

APFS space reporting combines statfs(2) for mount-level stats, a narrow parser for diskutil info -plist output for container-level free space, and tmutil listlocalsnapshots for snapshot discovery. Container allocation is not exclusive per-file ownership or a freed-space guarantee.

Compatibility

diskr is macOS-only, on Apple Silicon and Intel, with a minimum supported Rust version of 1.88.0. CI's maintained runtime floor is macOS 15, with native tests on macOS 15 and 26 for both architectures. Older macOS source builds are unverified, not deliberately blocked, and the target guard reports a clear error on Linux, Windows and unsupported CPUs.

The filesystem baseline is local APFS. Hardlinks, sparse files, inaccessible entries, filesystem identity and tool-output variations have fixture coverage; other filesystems and network volumes are best-effort, and mount exclusions remain visible. Headless frame tests cover 40, 80 and 120 columns with short and tall viewports, and native PTY smoke tests exercise keyboard input and clean shutdown. Identical glyph widths across every terminal, font or multiplexer are not promised.
