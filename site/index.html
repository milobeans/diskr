01 / Why diskr

Built around the questions you actually have.

Most disk tools stop at “this folder is big.” diskr keeps going until you know what to do about it.

  1. 01

    What is using the space?

    Live folder sizes sorted by what is really allocated on disk, with a share bar for every row. APFS clones, sparse files and compression distort apparent size, so diskr tracks both.diskr · S sizes everything visible

  2. 02

    What can I safely delete?

    Caches, build output, toolchains and package stores are found and labeled safe, regenerable or risky, each with the reason why.Tab to Reclaim · diskr --reclaim ~

  3. 03

    What changed?

    Folders that changed since their last scan carry a growth badge, and saved baselines show exactly what grew between two dates.B saves a baseline · diskr --diff ~

  4. 04

    Why doesn't free space add up?

    Mount totals, APFS container free space, what is actually available to you, and the local snapshots that can pin deleted data.diskr --space ~

  5. 05

    What are my dev tools costing me?

    Homebrew, Cargo, npm, pip and Bun packages, plus every project's node_modules, target and .venv, each with its size.p opens packages · diskr --packages ~

Files

Everything at a glance

Folders sort by allocated size the moment you open them. diskr only scans around what you are looking at, caches sizes between runs, and revalidates them with FSEvents so unchanged trees stay fresh without a rescan.

Hidden folders are where .ollama, .cargo and .npm quietly pile up. Press . and they are right there with the rest.

Projects

Drill into any project

Build directories are tagged only when their project markers are present: target next to a Cargo.toml, node_modules next to a package.json. A folder that merely happens to be called target is never a recommendation.

When you do want something gone, d moves it to the Trash after a confirmation.

⏎ open⌫ upd trashf Finder

Two passes find well-known caches and repeated build artifacts. Every finding explains itself, and the report never deletes anything on its own.

03 / Accuracy

Counts what is allocated, not what is claimed.

Docker's disk image says it is 64 GiB. It occupies 1.5. APFS clones, sparse files and compression all make a file's apparent size a poor guide to what deleting it gives back, so diskr sorts by allocated bytes and shows both when they differ.

Folders it cannot fully read are marked as lower bounds with ≥, never silently counted as zero.

06 / Install

Install in one line.

macOS on Apple Silicon or Intel. Prebuilt archives target macOS 15 or newer.

With Rust 1.88 or newer:

cargo install diskr

Then run diskr to browse your home folder, or diskr ~/Downloads to start somewhere specific.

Download the archive for your Mac and its checksum list from GitHub Releases, then verify before extracting. Run this in a new, empty directory:

case "$(uname -m)" in
  arm64) target=aarch64-apple-darwin ;;
  x86_64) target=x86_64-apple-darwin ;;
  *) echo "Unsupported architecture" >&2; exit 1 ;;
esac
archive="diskr-$target.tar.gz"
curl --fail --location --remote-name "https://github.com/milobeans/diskr/releases/latest/download/$archive"
curl --fail --location --remote-name "https://github.com/milobeans/diskr/releases/latest/download/SHA256SUMS"
checksum=$(awk -v archive="$archive" '$2 == archive { print }' SHA256SUMS)
test -n "$checksum" && printf '%s\n' "$checksum" | shasum -a 256 -c -

Only after the checksum verifies, install it:

tar -xzf "$archive"
mkdir -p "$HOME/.local/bin"
install -m 755 diskr "$HOME/.local/bin/diskr"
"$HOME/.local/bin/diskr" --help

Archives are not Developer ID signed or notarized; organization policy may require a different route. No quarantine bypass is needed or recommended.

From a local checkout:

git clone https://github.com/milobeans/diskr
cd diskr
cargo install --path .

Your disk is fuller than it looks.
